# Перевірка Medfarl AI System — 31 жовтня 2026

## Обсяг

Переглянуто структуру Python CLI, конфігурацію доступу, маршрутизацію агента,
реєстрацію інструментів, запуск команд у діагностичному агенті й кодері,
файлові операції, життєвий цикл сеансів, клієнт LLM та сценарії запуску.
Виправлення зосереджені на відтворюваних помилках терміналу, доступу й файлів.
Ця перевірка не доводить відсутності інших помилок у всьому проєкті.

## Виявлені й виправлені помилки

| Проблема | Виправлення |
|---|---|
| Копіювання/переміщення в той самий шлях із overwrite могло видалити джерело | Перевірка тотожності, hard links і вкладеності до видалення |
| Резервні копії за одну секунду мали однакові назви | Унікальний суфікс для кожної копії |
| Редагування не-UTF-8 тексту непомітно замінювало символи | Явна помилка замість запису пошкодженого тексту |
| EOF у багаторядковому shell додавав `exit` до буфера нескінченно | Повернення `/quit`, яке обробляється в обох режимах |
| Вивід Windows PowerShell декодувався як UTF-8 без налаштування самої оболонки | Явний UTF-8 та передавання скрипту через EncodedCommand |
| CMD отримував багаторядковий текст через `/c`, що не забезпечувало виконання всіх рядків | Тимчасовий UTF-8 batch-файл із прибиранням після виконання |
| Тайм-аут діагностичного shell завершував тільки батьківський процес | Завершення дерева процесів; збереження часткового виводу |
| Весь вивід команди накопичувався в пам’яті до обрізання | Тимчасові файли й обмежене читання результату |
| Невідома оболонка непомітно ставала PowerShell | Явна перевірка назви та зрозуміла помилка |
| `pwsh` маршрутизувався у Windows PowerShell | Окремий вибір Windows PowerShell та PowerShell 7 |
| Шляхи читання/cwd не розгортали змінні середовища | Спільне розв’язання шляхів |
| Інструкції агента вимагали підтверджень навіть у повному доступі | Узгодження інструкцій із поточним режимом |
| Перехід `/coder` не закривав інтеграції після завершення сеансу | `close()` у `finally` |

## Повний доступ

- Агент: `run-unsafe.bat` або `python main.py --agent --unsafe-full-access`.
- Кодер: `run-coder-full-access.bat` або `python main.py --coder --unsafe-full-access`.
- Прапорець або `MEDFARL_UNSAFE_FULL_ACCESS=1` тепер передається й кодеру.
  У цьому режимі його дії, включно з командами та інтеграціями, не запитують
  додаткового підтвердження. Режим планування продовжує блокувати зміни й команди.
- Підтримуються `powershell`, `pwsh` (якщо встановлено), `cmd`; кодер також
  підтримує `sh`, якщо вона встановлена.
- Доступ обмежений правами користувача ОС. Автоматичного підвищення прав немає.
- Кожна команда має окремий процес оболонки; змінні й поточний каталог не
  зберігаються між викликами. Для каталогу використовується параметр `cwd`.

## Перевірки та межі

Початкова база: 83 тести, одна пропущена перевірка. Додано регресійні перевірки
збереження файлів, Unicode, багаторядкового CMD, кодів завершення, обмеження
виводу, тайм-аутів і дочірніх процесів, cwd, EOF та прав кодера.

Команди виконуються реально в локальній Windows на нешкідливих прикладах;
файлові перевірки використовують тимчасові каталоги. Зовнішній Ollama, якість
відповідей моделі, антивірусні сканування, встановлення пакетів і реальні
сторонні MCP-сервіси не перевірялися наскрізно. Існуючий інтеграційний тест
терміналу більше не потребує прогрівання моделі й має обмеження часу.

Перевірка: `python -m unittest discover -s tests -q`.

Фінальний результат: 99 тестів, 98 успішних, один пропущений; помилок немає.
`compileall` та `git diff --check` також завершилися без помилок.

# Потокові відповіді в терміналі

Стан документації: 2026-10-24. [README](readme.md) · [Технічний опис](TECHNICAL.md).

Streaming увімкнено за замовчуванням: видимий текст друкується поступово під час
отримання від моделі. Типова модель —
`tripolskypetr/qwen3.5-uncensored-aggressive:4b`.
Потокове виведення не гарантує миттєвого першого токена: завантаження моделі,
обчислення та виконання інструментів можуть потребувати часу.

## Запуск

```powershell
.\run.bat
.\run-streaming.bat
.\run-coder.bat
python main.py --agent
```

`run.bat` — прямий чат без файлових і діагностичних інструментів.
`run-coder.bat` — кодер. `--agent` — діагностика ПК.
У меню пункт 16 відкриває потоковий чат, 18 — діагностику, 19 — кодер.

Для явного керування:

```powershell
python main.py --stream
python main.py --no-stream
python main.py --coder --no-stream
python main.py --coder --timeout 240
```

`--stream` повторно вмикає типову поведінку; `--no-stream` показує відповідь після
завершення генерації. Підтвердження дій потрібні в обох варіантах.
Лаунчер не закріплює окремої моделі: працюють `--model`, `MEDFARL_MODEL` і,
для кодера, `MEDFARL_CODER_MODEL`.

## Інструменти та виведення

Клієнт читає SSE-повідомлення з `POST /v1/chat/completions`. Видимі фрагменти
відповіді друкуються відразу. Частини викликів функцій збираються за індексом,
перш ніж кодер розбирає аргументи й виконує інструменти.

Кодер показує `[tool] назва`, а для змін файлів, команд, MCP і hooks — відповідні
підтвердження. Далі передає фактичні результати моделі. Усі виклики отримують
парні результати в історії. Відмова зупиняє поточне завдання, зберігаючи вже
виконані дії.

Якщо після виконання інструментів модель повернула порожній підсумок, кодер
показує звіт із фактичних результатів. Поля внутрішнього reasoning не друкуються
як готова відповідь. Деякі діагностичні відповіді формуються детерміновано й
можуть з’явитися одним блоком.

## Перевірка проблем

```powershell
python main.py --no-warmup --healthcheck
python main.py --coder --no-warmup --healthcheck
python main.py --list-models
```

Перша перевірка стосується доступності сервера й моделі; друга також перевіряє
приймання запиту з інструментами. Це не гарантія якості кожного виклику моделі.
Спробуйте `--no-stream`, щоб відрізнити проблему потоку від проблеми генерації.

`--skip-healthcheck` не вимикає попереднє завантаження моделі; для цього є
`--no-warmup`. Моделі не завантажуються з інтернету автоматично.
За замовчуванням запити йдуть у локальний Ollama; інший backend, мережеві
команди або MCP-сервер можуть передавати дані назовні.
